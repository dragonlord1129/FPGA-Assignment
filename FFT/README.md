# 8-Point Radix-2 FFT in Verilog

A synthesizable, fixed-point 8-point Radix-2 Decimation-In-Time (DIT) FFT,
with a self-checking testbench and a Python script that plots the results.
The design has been compiled and simulated with **Icarus Verilog**, and its
output was verified bit-for-bit (within fixed-point quantization error)
against `numpy.fft`.

## Files

| File                    | Description                                             |
|--------------------------|----------------------------------------------------------|
| `fft_top.v`               | Top-level FFT module (synthesizable)                     |
| `fft_tb.v`                 | Testbench — drives 3 test vectors, writes `fft_results.txt` |
| `plot_fft_results.py`     | Reads `fft_results.txt` and plots input/output for each test |
| `fft_results.txt`          | Generated by simulation (input + output samples)          |
| `fft_plot_*.png`           | Generated by the Python script (one per test case)         |

## How the design works

```
             bit-reversed          log2(N) sequential           natural-order
 input  --->  input load    --->      butterfly stages    --->    output
 (nat. order)  (into mem)         (N/2 butterflies/stage)
```

- **Fixed point format:** 16-bit signed, Q1.15 (1 sign bit, 15 fractional
  bits), representable range approximately `-1.0` to `+0.99997`.
- **In-place computation:** inputs are written into internal memory at
  bit-reversed addresses; after `log2(N)` butterfly stages the naturally
  ordered result sits in the same memory, so no extra reorder step is
  needed at the output.
- **Parallel butterflies, sequential stages:** all `N/2 = 4` butterflies of
  a stage execute in the same clock cycle (via a `generate` loop); the
  design advances through `log2(N) = 3` stages, one per clock cycle.
- **Twiddle factors** `W_N^k = cos(2πk/N) - j·sin(2πk/N)` for
  `k = 0 .. N/2-1` are computed once at elaboration time and stored in a
  small ROM.
- **Overflow protection:** every butterfly stage divides its outputs by 2
  (arithmetic shift), so the final result is the true DFT divided by `N`
  (the standard "scaled FFT" convention used in fixed-point hardware). The
  Python script scales the `numpy.fft` reference the same way for a fair
  comparison.

### Port list (`fft_top`)

| Port          | Dir | Width           | Description                              |
|---------------|-----|------------------|-------------------------------------------|
| `clk`           | in  | 1                | clock                                      |
| `rst_n`         | in  | 1                | active-low reset                           |
| `start`         | in  | 1                | pulse high for 1 cycle to begin a transform |
| `data_in_re`     | in  | `N*DATA_WIDTH`     | flattened array of real input samples (sample 0 in LSBs) |
| `data_in_im`     | in  | `N*DATA_WIDTH`     | flattened array of imaginary input samples |
| `data_out_re`    | out | `N*DATA_WIDTH`     | flattened array of real output bins        |
| `data_out_im`    | out | `N*DATA_WIDTH`     | flattened array of imaginary output bins   |
| `done`          | out | 1                | pulses high for 1 cycle when result is valid |
| `busy`          | out | 1                | high while a transform is in progress      |

Parameters `N` (default 8), `DATA_WIDTH` (default 16) and `LOG2N` (default
3, must equal `log2(N)`) can be overridden at instantiation, but the
twiddle-index and bit-reversal math is written generically, so re-checking
timing/overflow behavior is recommended if you resize the transform.

## Running the simulation

Requires [Icarus Verilog](http://iverilog.icarus.com/) (`iverilog` / `vvp`).

```bash
# Compile
iverilog -g2012 -o fft_sim fft_top.v fft_tb.v

# Run — this creates fft_results.txt in the current directory
vvp fft_sim
```

Expected console output ends with something like:

```
---- mixed_tones ----
bin 0 : re=0.199921  im=0.000000  mag=0.199921
bin 1 : re=0.149933  im=-0.000031  mag=0.149933
...
All tests complete. Results written to fft_results.txt
```

## Test vectors

The testbench (`fft_tb.v`) exercises three cases, each independently
verifiable by hand:

1. **`impulse`** — a unit impulse at `n=0`. Its DFT is flat, so every
   output bin should have magnitude `1/N = 0.125`.
2. **`sine_bin2`** — a pure sine wave completing exactly 2 cycles over the
   8 samples (amplitude 0.5). Energy should appear only at bins 2 and 6
   (`N - 2`), each with magnitude `0.5/2 = 0.25`.
3. **`mixed_tones`** — a DC offset plus a cosine at bin 1 and a sine at
   bin 3, to confirm several bins resolve correctly at once.

## Plotting the results

```bash
pip install numpy matplotlib
python3 plot_fft_results.py fft_results.txt
```

For each test case this produces a `fft_plot_<name>.png` with three panels:

1. Time-domain input samples fed to the hardware.
2. Magnitude spectrum computed by the Verilog FFT.
3. Reference magnitude spectrum from `numpy.fft` (scaled by `1/N`) for
   direct comparison.

It also prints the maximum absolute error between the hardware and
software results — with 16-bit Q1.15 fixed point this is on the order of
`1e-4` or smaller, i.e. quantization noise only.

## Notes on extending / synthesizing

- The design is written in synthesizable Verilog (no `real` types or
  transcendental functions in `fft_top.v` outside of the twiddle-ROM
  `initial` block, which most synthesis tools will accept as a constant
  initializer, or which you can replace with a literal lookup table for
  strict ASIC/FPGA flows).
- To change `N`, update `N`, `DATA_WIDTH`, and `LOG2N` together at
  instantiation. The bit-reversal function and butterfly indexing are
  general, but you should re-run the testbench to confirm no
  overflow/rounding surprises at the new size.
- For higher throughput, the sequential (one-stage-per-cycle) control FSM
  could be replaced by a fully-pipelined stage-per-hardware-block
  architecture at the cost of more logic area.
